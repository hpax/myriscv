This core implements the RV32I architecture, with the following
options (some of which can be enabled or disabled with parameters;
some are hard coded in the design).

See rtl/params.sv for the parameters available and their default
values. They are set as normal Verilog instance parameters.

Standard architecture extensions:

	I	- Base RV32I architecture
	B	- Bit operations (= Zba Zbb Zbs)
	C	- Compression operations (= Zca Zcb)
	Zkr	- Entropy source (*)
	Zkt	- Data-independent execution latency
	Zalrsc	- LR/SC instructions for atomicity (*)
	Zicbom	- Cache block management operations
	Ziccif	- Aligned instruction fetches are atomic
	Zicclsm	- Unaligned memory accesses
	Ziccrse	- LR/SC forward progress guarantee (*)
	Zicond	- Conditional integer operations
	Zicsr	- Control registers (*)
	Zictr	- Standard counter registers (*)
	Zmmul	- Integer multiplication
	Ztso	- Total store ordering (implicit in a uniprocessor)

	* = see below for non-standard, implementation-specific,
	    or configurable behavior

Private instruction set extensions:

	CUSTOM0 opcodes are used for custom I-type ALU instructions.
	CUSTOM1 opcodes are used for custom R-type ALU instructions.

	As for standard OP/OP-IMM instructions, all CUSTOM1 R-type
	opcodes with funct7 = 0000000 have the corresponding CUSTOM0
	I-type opcodes.

	In addition to these, many extended instructions are in
	brownfield space.

	Some extensions may be unconditionally enabled when
	STRICT_UNDEFINED = 0.

	WITH_Xpaicbom:
		The cbo.* instructions allow a memory offset to be
		specified, using the S instruction format. The
		standard form of these instructions always have all
		the bits of the S immediate set to zero, so the
		standard form is still valid.

	WITH_Xpabshsub: (req. Zba)
		shXsub	- shXadd funct7[5] = 1

	WITH_Xpaisetx:
		New SET instructions (no immediate forms):
			sge	- slt  funct7[1:0] = 10
			sgeu	- sltu funct7[1:0] = 10
			seq	- slt  funct7[1:0] = 01
			sne	- slt  funct7[1:0] = 11
		Condition "AND and equal zero":
			saeqz	- sltu funct7[1:0] = 01
			sanez	- sltu funct7[1:0] = 11

	WITH_Xpaicmpand:
		Condition "AND and equal zero" ("testz"):
			baeqz	- funct3 = 010
			banez	- funct3 = 011

	WITH_Xpabcinv (requires Zbb):
		Count the opposite polarity of bits:
			clo	- clz   rs2[4] = 1
			cto	- ctz   rs2[4] = 1
			cpopz	- cpop  rs2[4] = 1

	WITH_Xpabshone:
		Shift left/right insert ones -
			slo(i), sro(i)
			Same encodings as sll(i), srl(i) with
			funct7[6]/instr[31] = 1

		Shift right complement sign -
			srcs(i)
			Same encoding as sra(i) with
			funct7[6]/instr[31] = 1

	WITH_Xpabextr:
		Bitfield extraction custom opcode:

		extru   rd,rs1,rs2,wimm5
		extrs   rd,rs1,rs2,wimm5
		extrui  rd,rs1,shimm5,wimm5
		extrsi  rd,rs1,shimm5,wimm5

		With WITH_Xpabshone additionally ones or complement sign:

		extro   rd,rs1,rs2,wimm5
		extrcs  rd,rs1,rs2,wimm5
		extroi  rd,rs1,shimm5,wimm5
		extrcsi rd,rs1,shimm5,wimm5

		Extracts a sign- or zero-extended wimm5 bitfield from
		position rs2/pimm5 of rs1 into rd. wimm5 = 0
		represents 32 bits and is equivalent to a right shift.

		instr[6:0]	= 0001011 (CUSTOM0) for EXTR[US]I
				  0101011 (CUSTOM1) for EXTR[US]
		instr[11:7]	= rd
		instr[14:12]	= 101
		instr[19:15]	= rs1
		instr[24:20]	= rs2|shimm5
		instr[29:25]	= wimm5
		instr[31:30]	= 00 for EXTRU*
				  01 for EXTRS*
				  10 for EXTRO*
				  11 for EXTRCS*

	WITH_Xpabextn:
		Arbitrary width zero- or sign-extension:

		zext   rd,rs1,rs2
		zexti  rd,rs1,shimm5
		sext   rd,rs1,rs2
		sexti  rd,rs1,shimm5

		With WITH_Xpabshone additionally ones or complement sign:

		oext   rd,rs1,rs2
		oexti  rd,rs1,shimm5
		csext  rd,rs1,rs2
		csexti rd,rs1,shimm5

		A count of zero is treated as 32 bits and passes the
		value through unmodified.

		instr[6:0]	= 0101011 (CUSTOM1) for *EXT
		instr[11:7]	= rd
		instr[14:12]	= 111
		instr[19:15]	= rs1
		instr[24:20]	= rs2
		instr[29:25]	= 00000
		instr[31:30]	= 00 for ZEXT*
				  01 for SEXT*
				  10 for OEXT*
				  11 for CSEXT*

		The -i versions are not unique opcodes but assembly
		aliases for extr*i rd,rs1,0,shimm5.

	WITH_Xpaicneg:
		Conditional negate

		cneg  rd,rs1,rs2	rd = rs1 < 0 ? -rs2 : rs2
		cnegi rd,rs1,imm12	rd = rs1 < 0 ? -imm12 : imm12
		cnegn rd,rs1,rs2	rd = rs1 < 0 ? rs2 : -rs2

		instr[6:0]	= 0001011 (CUSTOM0) for CNEGI
				  0101011 (CUSTOM1) for CNEG, CNEGN
		instr[11:7]	= rd
		instr[14:12]	= 110
		instr[19:15]	= rs1
		instr[31:20]	= imm12 for CNEGI
		instr[24:20]	= rs2 for CNEG[N]
		instr[29:25]	= 0000000 for CNEG
				  0100000 for CNEGN

		"abs rd,rs1" is an alias for "cneg rd,rs1,rs1".

	WITH_indcsr:
		Indirect CSR access.

		Functionally implemented as using custom CSR numbers
		0xbe0-0xbff to indicate that actual register number
		should be accessed via x0..x31. This can also be seen as
		rs2 = register number, funct7 = 1011111.

		XXX: this support may be discontinued if a CSR
		register file is motivated.

	WITH_Xpacecall:
		Additional RVC encoding:
			c.ecall	- opcode 0x8002

Non-standard or system-specific behaviors:

	With FUSE_CNOP:
		An RVC instruction immediately followed by c.nop, as
		is sometimes added by tools due to padding, can be
		treated as a 32-bit instruction and executed in a
		single cycle. The c.nop instruction is functionally
		skipped and will not increment the instruction retired
		counter.

	Without STRICT_UNDEFINED:
		A number of instruction encodings alias others or
		perform undefined operations rather than trap. This
		reduces the decoding logic.

		The Xpaicbom and Xpacecall instructions end up
		automatically being supported, de facto.

		The following guarantees will always be maintained,
		now and in the future, unless enabled by explicit
		extensions:

		- All zero memory will trap.

		- op[3:0] = 1111 (thus all-one memory) will trap.

		- ecall and ebreak with rs2, rs1, or rd nonzero will
		  trap, but may report ECALL or EBREAK in the mcause
		  CSR.

		- Memory loads will only be generated by LOAD,
		  LOAD-FP, AMO, MISC-MEM, or CUSTOM2 opcodes.

		- Memory stores will only be generated by STORE,
		  STORE-FP, AMO, MISC-MEM, or CUSTOM3 opcodes.

	CSR instructions:
		Undefined/unimplemented CSRs read as 0; write are
		ignored.

	Zictr counters:
		Each counter width can be set to any value from 0 to
		64. If the cycle counter is set to 0 bits the time
		counter value is returned.

		The time counter can be external.

		None of the counters are writable.

	LR/SC instructions (WITH_Zalrsc):
		There is only one reservation bit.

		It is claimed by LR and released by SC, exceptions,
		and interrupts.

		If WITH_Ziccrse is specified, interrupts are inhibited
		until up to 2^Ziccrse_bits instructions (default 2^4)
		have been retired, or if Ziccrse_bits == 0,
		indefinitely until the reservation has been cleared.

		Unless STRICT_UNDEFINED is set, halfword and byte
		LR/SC instructions (lr.b, lr.h, lr.bu, lr.hu, sc.b,
		sc.h) are supported by setting funct3 to the same
		value as the equivalent load or store instruction.

		There is currently no support for LR/SC to I/O or to
		prevent DMA to external memory.

	WITH_Zkr:
		Enable the Zkr random number generator architecture
		(seed CSR.) This requires an external source of random
		bits.

		The Zkr unit contains an LSFR for entropy buffering
		and bitstream whitening. This is considerably weaker
		than one using cryptographic whitening; if that is
		considered necessary then the bitstream needs to be
		whitened externally, or rtl/rng.sv modified.

		The following ports are used for the random number
		generator inputs:

		input tri0 rng_data;	// Data bit
		input tri1 rng_stb;	// Data strobe
		input tri0 rng_incr;	// Increment entropy counter
		input tri0 rng_bist;	// RNG running built-in self test
		input tri1 rng_dead;	// RNG permanent failure

		output rng_full;	// Entropy buffer saturated

		When rng_full is set, the it is reasonable to clock gate
		or power down the RNG bit source.

		Pulsing rng_stb on data is optional; if left to its
		default value of 1 it will continously stir the
		entropy buffer. This is potentially advantageous for a
		non-perfect bit source.

		rng_incr should be pulsed when enough data bits have
		been received to count as one bit of true
		entropy.

		The parameter Zkr_secure (default 1) controls if the
		value currently in the entropy accumulator should be
		masked if the entropy buffer is not currently full.
		Setting it to 0 reduces logic (and might be useful for
		running BIST on the CPU itself) at the cost of
		security.

		It might be useful to feed some combination of
		rng_full, rng_bist, and rng_dead to an external interrupt.

		When rng_full is signalled, the seed CSR status field
		will report either BIST, ES16 or DEAD. DEAD is
		reported if rng_dead is asserted; BIST is reported if
		rng_bist is asserted or has been assered since the
		last CSR read; otherwise ES16 is reported. Notably,
		when rng_full is signalled, the state is not WAIT
		(signal propagation delay excepted.)

		Although the default entropy buffer is the
		architecturally defined 16 bits, it can be configured
		to any value between 1 and 30 bits by setting the
		Zkr_bits parameter; the seed CSR will contain that
		number of data bits; the "ES16" status is signalled
		after that many received bits. A suitable LSFR
		polynomial is automatically chosen based on the
		Zkr_bits configuration.


Nonstandard CSR numbers:

	0x7f0		USER_CONTEXT
	0x7f1		(reserved)
	0x7f2		CIE
	0x7f3		WAITFOR
	0x7f4		SYS_CONTEXT
	0xbe1-0xbff	Used for indirect CSR access (x1-x31)

System architecture:

	The system architecture is only partly compatible with the
	standard RISC-V privileged system architecture.

	This is intended for microcontroller applications, and does not
	implement any kind of protection; in effect only the machine
	privilege level exists.

Register contexts:

	The main intended target of this CPU is FPGAs, and FPGAs tend
	to have relatively large RAM arrays (except for a minority of
	architectures which also allows the LUT tables to be used as
	very fine grained RAM.) Thus, this CPU tries to take advantage
	of a "forced large" register file by providing multiple
	register contexts (register banks.)

	One register context (machine context, context 0) is used for
	interrupts/exceptions; the CPU will automatically switch to
	this context, and return when executing MEPC.

	There are no scratch register CSRs; however, software can
	reserve register contexts for scratch if needed.

	The "user_context" CSR contains the current user context; the
	operating system can set this to quickly switch
	tasks. user_context is *not* changed when going to machine
	context or when transferring to a specific context with the
	.sc instructions (which are intended primarity for switching
	to machine context.) The user context CSR is writable.

	The optional "sys_context" CSR (WITH_sys_context) contains the
	currently executing context. This is set to on interrupts,
	exceptions or when using the .sc instructions (see below); it
	is set to user_context when the mret instruction is executed.
	It is a readonly CSR if enabled; the underlying register
	always exists.

	The following special instructions are provided that provide
	access across register contexts. CUSTOM1 is used for register
	forms; if funct7 == 0000000 then also have immediate (CUSTOM0)
	forms.

		add.xu	- funct3 == 000, funct7 == 0000000
		sub.xu	- funct3 == 000, funct7 == 0100000
		  	  rs1 is forced to the user context.

		add.ux	- funct3 == 001, funct7 == 0000000
		sub.ux	- funct3 == 001, funct7 == 0100000
			  rd is forced to the user context.

		add.xc	- funct3 == 000, funct7 == 10ccccc 
		sub.xc	- funct3 == 000, funct7 == 11ccccc 
		  	  rs1 is forced to the context in insn[29:25].

		add.cx	- funct3 == 001, funct7 == 10ccccc 
		sub.cx	- funct3 == 001, funct7 == 11ccccc
		  	  rd is forced to the context in insn[29:25].

		add.su	- funct3 == 011, funct7 == 0000000
		sub.su	- funct3 == 011, funct7 == 0100000
		add.sc	- funct3 == 011, funct7 == 10ccccc
		sub.sc  - funct3 == 011, funct7 == 11ccccc
			  rd is forced to user context (.su) or the
			  context in insn[29:25] (.sc), and the CPU
			  switches to that context before executing
			  the next instruction. user_context, mepc or
			  any of the other machine status registers
			  are unaffected.

			  This is intended to be used to implement
			  fast locking operations in an RTOS as it
			  avoids having to dispatch an machine
			  handler. The register written can be used
			  as an argument without needing to use
			  add.xu to fetch it, or for other purposes.

			  If writing a register is not wanted, just
			  set rd == x0.

			  The assembler implements the suffix .sm as
			  an alias for .sc with context 0
			  (CTX_MACHINE).

	The total number of contexts is set with the parameter
	CONTEXTS. This must include the machine context and at least
	one user context (so minimum 2); the maximum number of
	contexts is 32 as the CIE CSR (see below) is a bitmask. The
	number of contexts does not have to be a power of 2, although
	in an FPGA it makes sense to make it support the *addressable*
	size of the RAM arrays.

	See implementation.txt for details of the hardware resource
	costs of contexts.

	User contexts range from CTX_MIN_USER to CONTEXTS-1.
	Currently the only system context is machine context
	(CTX_MACHINE == 0), but in the future it might be possible to
	configure additional contexts like NMI and/or debug
	contexts. Thus, if CONTEXTS == 8, in the current
	implementation user contexts range from 1 to 7.

	After reset, user_context contains CTX_MIN_USER.

	The optional readonly ncontexts CSR (WITH_ncontexts) contains
	CTX_MIN_USER in bits [7:0] and CONTEXTS-1 in bits [15:8],
	representing the valid range of user contexts.

	The .xc/.cx instructions make it possible to reserve one or
	more contexts for use as scratch registers, if so would be
	necessary or useful.


Interrupts:

	Up to 31 interrupt request lines are supported, strictly
	prioritized, numbered from 1 to 31 and configurable by the
	NUM_IRQS parameter. IRQ 1 has the highest priority.

	IRQ 0 is reserved for future CPU-generated interrupt
	conditions and/or NMI.

	Note: the CPU top level ports include IRQ 0. This is a
	convenience for simulation and to avoid additional complexity
	for the case of NUM_IRQS == 0. The inputs for IRQ 0 are all
	ignored.

	The interrupt vector number is reflected directly in mcause
	(with bit 31 set); the architectural definition of interrupt
	causes 0-15 are ignored.

	Each register context has a separate interrupt flag, given as
	a bitmask in the "cie" CSR (context interrupt
	enable). Normally the interrupt flag in machine context would
	be left at 0, of course. If the parameter WITH_mstatus is
	enabled, the standard mstatus CSR acts as a "window" into this
	CSR, with bit 1 corresponding to the flag for the current user
	context, and bit 3 to the currently active context (user or
	system, as the system is currently running in.)

	The mie and mip CSRs contain the currently pending and enabled
	interrupts as a bitmask. This is at least partially nonstandard.

	Interrupts can be level- or edge-triggered. If edge-triggered,
	they are cleared either on the interrupt begin accepted or by
	writing 1 to the corresponding bit(s) in the mip register.

	The mtvec CSR is writable if and only if the parameter
	MTVEC_WMASK (default 0) is set to a mask of permitted bits.

	Bit 1 in mtvec is treated as a PC bit if enabled (which it normally
	should not be.) Bit 0 in mtvec controls vectoring of interrupts
	if enabled (IRQ_VECTOR_BITS != 0). If this bit is set in
	MTVEC_RESET and clear in MTVEC_WMASK, interrupt vectoring is
	unconditionally enabled.

	If vectoring is to be enabled, it is highly recommended that
	(MTVEC_RESET | MTVEC_WMASK) [IRQ_BITS+IRQ_VECTOR_BITS-1:0] == 1
	in order to reduce logic.

	The following ports on the CPU top level are used for interrupts.
	All ports are optional (triX), with the default values shown

	input tri0 [NUM_IRQS:0] irq;		// IRQ signal mask
	input tri0 [NUM_IRQS:0] irq_edge;	// IRQ edge triggered
	input tri1 [NUM_IRQS:0] irq_intable;	// IRQ can generate interrupt
	input tri1 [NUM_IRQS:0] irq_waitable;	// IRQ can be a waitfor source

	output [IRQ_BITS-1:0]   intack;	// Interrupt acknowledgement if nonzero

	irq_edge can be changed at runtime, although that will require
	additional logic resources for any IRQs where this is not constant.

	irq_intable and irq_waitable are provided to reduce
	unnecessary logic if not all IRQs need to support being
	enabled as interrupts alternatively waitfor triggers (see
	below) and should be fed with constants in a real system;
	feeding them with variable parameters will increase the logic
	burden over simply setting them to all 1. They are ports
	rather than parameters for the benefit of simulation only.

Reset condition:

	pc			= RESET_PC (default 0x10)
	mtvec			= MTVEC_RESET (default 0x80)
	user_context		= CTX_MIN_USER
	executing context	= 0 (machine context)
	cie			= 0

	Values are CPU parameters and their default values unless otherwise
	stated.

CSRs:

	Currently, nonexistent CSRs always return 0, and writes are ignored.
	The same is true for writes to undefined CSR bits.
	No traps are implemented for any CSR operations.

WITH_waitfor:

	Writing a mask to the "waitfor" CSR will wait until any
	of the interrupt sources in the mask become pending in the mip
	register, whether or not they are enabled in either mie or
	cie. If an interrupt arrives that *is* enabled in mie and cie,
	it will be taken; mepc will point to the successor to the csrw
	waitfor if this interrupt is in the wait mask, otherwise it
	will point back to the csrw waitfor instruction itself. Thus,
	this can be used with interrupts enabled to enforce that a
	certain interrupt has been received and its handler executed,
	*or* to wait for an interrupt line that in fact never needs to
	be enabled and is simply used as a ready signal from external
	hardware.

	waitfor is a write-only CSR and always reads 0.
